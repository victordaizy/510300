# 510300 压力传导危险率 V2：G0.1 修复后版本锁定与独立复演协议 V1

## 1. 目的与边界

本协议只回答一个工程问题：历史修复后的 G1 结果，是否能够从一个本地 Git 锁定提交，在新建的独立工作树和新进程中，依赖逐文件冻结的数据身份被精确复演。

本协议不授权正式或反事实 G2，不拟合 B1、B2、B3 模型，不读取收益、净值、夏普、回撤或持仓，不连接券商，也不产生 Paper、Shadow、订单或实盘动作。成功完成 G0.1 只表示版本与数据可复演，不表示策略、机制或经济假设有效。

## 2. 只增不改原则

- 保留既有配置、清单、状态、收据和数据文件，禁止覆盖。
- G0.1 的 manifest、冻结收据、独立工作树复演收据和最终状态均使用新的版本化路径。
- 当前脏工作树中的无关文件不得进入锁定提交。
- 大型 Parquet 与原始数据可以不进入 Git，但必须进入受 Git 跟踪的 G0.1 manifest；每个文件至少记录项目相对路径、字节数和 SHA-256。
- 每个 Parquet 还必须记录行数、列数、列顺序和持久化语义摘要。
- 不要求远程推送；本地提交是必要条件。

## 3. G0.1 执行顺序

1. 在专用分支 `codex/510300-v2-g0-1-g1b-v1` 上冻结 Git 范围、父证据身份和外置数据身份。
2. 将冻结范围与 G0.1 manifest、冻结收据一起提交到本地 Git。
3. 从该精确提交新建 detached 独立工作树；不得从当前脏工作树直接声称复演通过。
4. 按 manifest 将未跟踪数据只增不改地物化到独立工作树。若目标文件已经存在，仅允许身份完全相同时复用；身份不同则立即停止，不得覆盖。
5. 在新进程中执行修复后的完整 G1 数据构建，并与冻结的九个 Parquet 输出逐表精确比较。
6. 同时核对 G1 门状态、门结果载荷、31 个 B2 可识别独立事件、1,102 个 B2 合格非事件风险日、1,279 个 B2 common/view 日及固定年代分布。
7. 复演收据先在独立工作树只增不改地生成，再复制回主工作树；最终状态只能在验证提交内容、数据身份和复演收据后生成。

## 4. 通过条件

G0.1 仅在以下条件全部成立时为 `PASS`：

- 既有 G0、G1 修复配置、清单、构建收据、复演收据、纠正后状态及状态纠正收据身份均未漂移。
- 锁定提交包含 manifest 声明的全部 Git 文件，且提交内字节与冻结身份一致。
- 独立工作树 HEAD 等于锁定提交，所有受 Git 跟踪文件干净。
- manifest 自包含摘要有效，全部外置数据文件身份一致，所有 Parquet 的持久化语义一致。
- 新进程复演的九个输出表在列、dtype、行顺序和数值语义上与冻结输出一致。
- G1 复演状态为 `PASS_B2_MECHANISM_ONLY_B3_NOT_IDENTIFIABLE`。
- B2 可识别独立事件数为 31；B2 合格非事件风险日为 1,102；B2 common sample 与 M/F/T view 日均为 1,279。
- 固定年代分布保持为：2015–2017 为 0/10，2018–2020 为 5/15，2021–2023 为 19/22，2024–2026 为 7/11；分子为 B2 可识别事件，分母为年代内全部事件。

任一条件不满足时，不得生成 PASS 状态，也不得继续 G1B 或 G2。

## 5. G1B 的后续关系

G0.1 通过后，才能另行冻结 `G1B_PREQUENTIAL_ERA_IDENTIFIABILITY`。G1B 的冻结必须发生在读取其允许字段值之前。G0.1 不预判或替代 G1B；G1B 若不足三个合格年代，状态应为 `NO_VIEW_INSUFFICIENT_EVALUABLE_ERAS`，正式 G2 保持 `NOT_RUN_BLOCKED_BY_G1B`。

## 6. 状态语义

- `PASS_G0_1_POST_REMEDIATION_VERSION_LOCK_AND_CLEAN_REPLAY`：仅表示锁定提交与外置数据能够精确复演修复后的 G1。
- `MODEL_TRAINED=FALSE`：本门没有拟合任何模型。
- `RETURN_EVALUATION=NOT_ALLOWED`：本门没有读取或评价任何收益与组合结果。
- `POSITION_IMPACT=0`：本门不改变仓位或交易权限。
- G0.1 的 PASS 不是 G2 授权，不是历史策略接受，也不是外部专家审阅结论。
