# VAL01_NORM_EY_5Y 财务历史扩展协议 V1

## 1. 目的与边界

本阶段只补齐 `VAL01_NORM_EY_5Y` 固定定义所需的历史财务原始档案，并重跑可重建性覆盖闸门。它不计算未来收益、IC、策略净值、仓位、股数或订单，也不连接券商。

原始点时财务档案 `csi300_financials_point_in_time.parquet` 和原 132 个 VIP 检查点已经冻结，不得改写。本阶段必须使用独立检查点目录、独立扩展事件表和独立合并档案；采集前后均校验冻结文件哈希和冻结检查点目录内容哈希。

## 2. 历史下界推导

首个必需信号月为 2016-08。按当时已披露信息，通常可选的最新报告期是 2016-06-30。固定三年正常化窗口的下界因此是 2013-06-30。

半年报 TTM 采用“本年半年累计值 + 上年年报累计值 - 上年半年累计值”。计算 2013-06-30 的 TTM 必须同时拥有 2013-06-30、2012-12-31 和 2012-06-30。因此原始财务补采下界固定为 2012-06-30，而不是只为凑足四个观察从 2014 年开始。

闭区间 2012-06-30 至 2015-06-30 共 13 个季度；三张 VIP 表的基础检查点共 39 个。2015-09-30 只作冻结档案重现性和接口语义交叉核验，不并入扩展事件表。

## 3. 目标证券范围

目标证券固定为 2016-08 至 2021-07 这 60 个官方月度权重快照的证券并集。当前冻结权重档案对应 516 只证券。扩展原始响应保留全市场检查点，但构建扩展事件表时只保留这 516 只目标证券。

该设计既避免把研究范围扩成全 A 股模型，也保留供应商原始响应，以便核验目标证券是否因单次返回边界而缺失。

## 4. 官方接口与字段

使用 Tushare `income_vip`、`balancesheet_vip`、`fina_indicator_vip` 按报告期获取全市场季度数据。三者的官方文档均说明，季度全市场 VIP 调用需要 5000 积分。

- 利润表：`ts_code, ann_date, f_ann_date, end_date, report_type, revenue, n_income_attr_p`。
- 资产负债表：`ts_code, ann_date, f_ann_date, end_date, report_type, total_hldr_eqy_exc_min_int, total_share`。
- 财务指标：`ts_code, ann_date, end_date, eps, dt_eps, bps, roe`。

利润表和资产负债表以 `f_ann_date` 为首选可得日，缺失时回退 `ann_date`；财务指标表不提供 `f_ann_date`，使用 `ann_date`。金额单位按官方字段语义保留为人民币元，总股本为股，每股字段为元/股。

## 5. 完整性与单次返回边界

官方文档没有给出三个 VIP 季度接口的分页参数，因此不得声称全市场响应天然完整。每个季度/API 必须记录：原始行数、唯一证券数、精确重复数、目标证券数、字段完整性、报告期一致性和文件哈希。

目标证券完整性采用两层闭环：

1. 以 VIP 全市场季度响应为主体；
2. 以冻结的 2015-09-30 检查点为后端锚，对每只目标证券在首次出现之后的季度连续性做缺口检查；发现缺口时，先按证券调用一次对应非 VIP 历史接口，再按报告期拆分补齐。单证券历史响应若达到官方100行边界，或批量响应仍缺少目标报告期，才退回逐报告期确认。空响应也必须原样留痕，不能被当成网络成功或数据存在。

这个闭环只证明“目标证券范围内当前供应商档案的可取得性”，不证明全市场响应完整，也不证明供应商历史值从未修订。

## 6. 传输与凭据

令牌只能从进程环境或被 Git 忽略的 `.env` 读取，报告和日志不得保存或回显令牌。允许标准 Tushare 令牌或代理令牌，但 API URL 必须是 HTTPS；代理 HTTPS 失败时必须停止，禁止自动降级到明文 HTTP。

请求间隔固定为不低于 0.5 秒；代理端点在实采中两次触发6分钟冷却，因此后续续跑采用 6.0 秒保守间隔（约10次/分钟）。检查点采用先写临时文件再原子替换的方式，支持断点续采。

## 7. 点时语义和历史修订边界

扩展事件表按 `con_code + report_period + available_at` 合并三张表，并保留供应商的多公告版本。任何信号日只能选择 `available_at` 不晚于该日的最新版本。

但是本次原始值在 2026 年统一回取。`available_at` 可以重建“当时何时公开”，不能证明当前供应商档案中的数值在历史上从未被追溯修订。因此即使覆盖闸门通过，状态也只能是 `PASS_PIT_RECONSTRUCTION_WITH_CURRENT_ARCHIVE_CAVEAT`，不能称为原生历史快照。

## 8. 验收与停止规则

只有同时满足下列条件，才允许生成扩展合并档案并进入覆盖重跑：

- 39 个季度 VIP 基础检查点全部存在并通过字段/报告期校验；
- 目标证券连续性缺口均已由单证券接口补齐或以空响应确认；
- 扩展事件表不存在重复点时键，公告日不晚于可得日；
- 扩展报告期严格早于原档案首期 2015-09-30；
- 原财务文件哈希、原 132 个检查点数量和目录内容哈希在采集前后完全一致；
- 五年窗口的标准化盈利权重覆盖逐月不低于 90%。

若安全 HTTPS 端点、凭据、权限、字段、报告期、目标连续性或冻结哈希任一项失败，状态必须是对应 `BLOCKED_*`，停止在数据层。不得以缩短历史、改变四观察门槛、删除早期月份或提前查看收益来绕过。
