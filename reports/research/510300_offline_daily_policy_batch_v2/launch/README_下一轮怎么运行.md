## 一、运行方法

把本次已经上传的 `510300_纯日线低频政策_results_run1_20261002.zip` 放在本文件、`run_next.py`、`reference_engine.py`、`reference_rules.json` 同一个目录。不解压源ZIP。

在该目录打开PowerShell，使用Python 3.10或更新版本：

```powershell
python .\run_next.py --self-test
python .\run_next.py --out .\results_run2
```

源ZIP在其他位置时：

```powershell
python .\run_next.py --source "C:\实际目录\510300_纯日线低频政策_results_run1_20261002.zip" --out .\results_run2
```

程序先校验源ZIP、继承引擎和参数的哈希，再运行合成检查。输出目录非空时停止，不覆盖旧结果。

随后先原样重放第一轮24份账户，与上传的逐日账本逐字段比较。全部通过后才运行8份新账户。若原对照不能复现，程序停止，不静默继续产生新绩效。

## 二、仅两项新实验

### T：TREND_NO_SLOPE

父版本：TREND。

唯一规则变化：删除入场时“MA60高于20个交易日前MA60”这一条件。

保持连续两个收盘高于MA60才允许形成新趋势信号；连续两个收盘低于MA60退出。持仓期间没有新增的最短持有期。均线窗口、两日确认、风险预算、费用和执行均不改变。

问题：额外斜率条件避免的错误交易，是否值得其带来的确认延迟？

反例：删除斜率可能更早买入下跌中继，增加震荡亏损。原数据中，所有42次“价格刚上穿MA60但斜率仍弱”的20日描述性收益中位数为负；不能根据9·24单例默认删除条件会改善结果。

### R：REPAIR_SEQUENCE

父版本：REPAIR。

原式要求同一天同时z5<-2并收涨。新版本保留z5定义和-2阈值，将“已出现超跌”记忆到一个有限准备期。

1. 无活动修复信号且没有准备期时，第一次z5<-2的收盘启动准备期。
2. 重复出现z5<-2不重置准备期起点。
3. 最多观察原参数中的10个交易日步长：准备期年龄达到10时先到期；价格已达到MA5时先取消，不能追认剩余修复空间。
4. 在未到期的准备期内，第一次收盘总回报价格高于前日、且仍低于MA5，形成活动信号。起始当日同时满足也允许，因此保留原来同日确认的可能。
5. 活动信号的价格锚、风险尺度和10日有效期均从确认日建立，完全沿用原REPAIR的活动期定义：到MA5、跌破确认价锚的3倍信号日波动保护线、或活动信号年龄达到10，任一结束。
6. 活动信号结束当日不重新进入。准备期终止当日也不重新启动。
7. 订单未成交不刷新信号年龄；原引擎按下一日仍有效的目标重新决定。

**准备期最多10日、活动信号期另最多10日；两阶段总长度可能接近20日。不能将其称为仅改变同一天判断而完全不改变机会集合。**准备期10日复用已有参数作为公开种子，未搜索更优天数。

问题：先发生超跌、随后才恢复的过程，能否比强迫二者同日发生取得有意义的净优势？

反例：准备期可能把持续阴跌中的小反抽误认为修复；确认等待也可能耗尽收益空间。允许更多机会不等于提高期望。

## 五、事前判断标准

T比较提前参与了什么上涨，同时增加了什么失败；不能只看9·24。R比较实际交易机会、净期望和尾部；不以次数或胜率上升自动判断成功。两者均与VOL10、原父策略及买入持有比较完整净值与风险。

出现经济增量且不只依赖单一事件，才登记后续稳健性和冻结前瞻阶段。区间、实施成本和历史选择风险另行检验，不直接晋升实盘。未见增量时结束本批设置，不自动改确认天数、窗口和权重。

这批本身是已看过历史之后的明确再开发。得到更高点值也不能叫独立样本外通过。所有参数修改都会产生新版本和新试验记录。
