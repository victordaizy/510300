# V2 G1 事件预测准入 V1.0.1：重放文件身份比较修正

修正 ID：`510300_STRESS_TRANSMISSION_HAZARD_V2_G1_EVENT_PREDICTION_ADMISSION_V1_0_1`  
范围：`FILE_EVIDENCE_COMPARISON_SUBSET_ONLY`  
研究状态：`DISCOVERY_ONLY`  
仓位影响：`0`

## 原始失败

V1 构建已成功写入三张表。首次洁净重放在核对第一张表时报告“文件身份漂移”。
只读复核确认，实际文件的 `path`、`bytes` 和 `sha256` 与构建收据完全一致。

失败原因是 V1 校验器把 `file_evidence()` 返回的三个身份字段，与同时包含
`row_count`、`persisted_semantic_sha256` 的完整输出元数据字典直接比较。两个字典
键集合不同，因此真实文件未漂移也会失败。

V1 manifest、代码、构建表、构建收据和失败收据全部保留，不修改、不覆盖。

## 唯一修正

V1.0.1 只允许：

1. 从构建收据的输出元数据中提取 `path`、`bytes`、`sha256`；
2. 用这三个字段核对实际文件身份；
3. 继续单独核对 `row_count`；
4. 继续单独核对持久化语义摘要；
5. 继续逐值比较重建表与持久化表。

任何实际路径、字节数、SHA-256、行数、列、值、顺序或语义摘要差异仍然失败。

## 明确不变

- 不重写三张 G1 数据表；
- 不改变 B1 公式；
- 不改变 BAD10 标签、-4% 阈值或 10 日期限；
- 不改变共同样本、事件权重或 G1 的 30/40/750 门槛；
- 不读取 `minimum_path_return` 或其他实际未来路径幅度；
- 不拟合 B0、B1、B2、B3；
- 不生成概率、预测指标、警报、组合收益、净值、夏普或回撤；
- 不产生仓位、订单、Paper/Shadow 或经纪商动作。

原始构建得到的 23 个 B2/B3 可识别事件在修正重放完成前只是待复验结果；
只有 V1.0.1 全量重放和冻结测试通过后，才写入正式 G1 状态。
