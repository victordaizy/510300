# 510300 T_ONLY_FORWARD_V1.1 直接使用指南

## 1. 你每天只需要看什么

每个交易日16:30后打开：

`reports/forward/t_only_forward_v1_1_daily_guide.md`

先看四项：行情截止日、系统状态、今日结论、下一交易日影子动作。盘中不预测、不临时改规则、不把前一日操作卡延用到新的一天。

当前系统是 `T_ONLY`，只做趋势模块。均值回归/类马丁模块没有通过历史否证，因此不参与这条前瞻账本。

## 2. 决策顺序

1. `daily_run_status.json` 的退出码不是0：无视所有旧信号，状态为 `NO_VIEW`。
2. 数据闸门不是 `PASS`：无操作。
3. 行情截止日不是最新完整交易日：无操作。
4. 每日操作卡没有 `model_action`：无操作；若影子账本已有仓位，则维持原影子仓位。
5. 有 `model_action`：只把它记为下一交易日开盘的影子动作，不在信号当天收盘后追价。

## 3. 可能出现的全部动作

| 信号 | 含义 | 下一交易日开盘影子目标 |
|---|---|---:|
| `TREND_ENTRY` | 完整周为多头，且收盘突破此前20日最高价 | 32.5% |
| `TREND_ADD_2` | 多头状态持续，价格较上次成交再上涨1个冻结ATR | 65.0% |
| `TREND_ADD_3` | 再上涨1个冻结ATR | 97.5% |
| `TREND_EXIT_WEEKLY_BEAR` | 完整周转为空头 | 0% |
| `TREND_EXIT_DONCHIAN_10` | 收盘跌破此前10日最低价 | 0% |
| `TREND_EXIT_2ATR_STOP` | 收盘跌至上次成交价下方2个冻结ATR | 0% |

没有第四次加仓，不做盘中补仓，不做下跌摊平，不在同一天同时买卖。

## 4. 2万元账户如何理解目标仓位

目标仓位是总权益比例，不是“再买对应比例”。模型内部按下一交易日开盘价重新计算目标总份额，并向下取100份整数倍：

`目标份额 = floor(目标仓位 × 开盘时总权益 ÷ 开盘价 ÷ 100) × 100`

交易差额等于目标份额减去已有份额。正常调仓名义金额必须不少于5,000元；风险清仓可以豁免5,000元门槛。模型费用为每腿 `max(成交额×0.03%, 5元)`，另计单边5bp滑点。

以总权益20,000元、开盘价4.80元为纯说明示例：

| 目标仓位 | 目标份额示例 | 名义市值示例 |
|---:|---:|---:|
| 32.5% | 1,300份 | 6,240元 |
| 65.0% | 2,700份 | 12,960元 |
| 97.5% | 4,000份 | 19,200元 |

示例不是当天订单。实际开盘价、真实账户权益、已有份额、可用资金、佣金和成交偏差会改变数量；当前系统未获授权读取这些真实账户字段。

## 5. 每日时间表

### 收盘前

- 不根据盘中突破提前行动。
- 不人工猜测周线状态。
- 不修改20日/10日/ATR/仓位参数。

### 16:30以后

- 等待自动任务结束。
- 打开每日操作卡。
- 核对行情截止日、数据闸门和今日结论。
- 若出现影子动作，只登记为“下一交易日开盘待验证”。

### 下一交易日

- 影子账本按开盘价及冻结滑点/佣金模拟执行。
- 当天收盘后再次运行时，核对是否实际写入 `execution_events.csv`。
- 若数据失败或交易日历覆盖不足，系统输出 `NO_VIEW`，不得沿用旧动作。

## 6. 周线为什么不会每天改变

周一至周四只能使用上一个已完成交易周的状态。只有上交所交易日历认定的当周最后交易日，才能使用本周聚合状态。节假日前的最后交易日可能不是星期五，系统以冻结交易日历为准。

## 8. 实盘边界

这套系统目前可以直接用于“每天查看、记录和执行影子账本”，不能被表述为已经验证可实盘。至少需要252个新交易日、3个闭合周期并通过全部冻结门槛，才有资格讨论是否建立新的实盘授权版本。

在此之前，如果使用者自行用真实资金跟随，应当明确视为个人主动承担的未成熟样本外实验；系统本身不生成真实订单、不映射真实持仓、不连接券商。
