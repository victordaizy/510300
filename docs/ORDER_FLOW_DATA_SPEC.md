# PV/LC订单流数据规范

## 当前决定

PV、LC维度有潜在价值，但现在不是“用不上”，而是缺少能够合法计算它们的原始Level-2数据和双方确认过的数学定义。项目保持`BLOCKED_WAITING_FOR_LEVEL2_SAMPLE_AND_PV_LC_DEFINITION`，不得用日线、1分钟或15分钟OHLCV伪造。

## 原始数据必须包含什么

试样至少覆盖510300连续20个交易日，优选60个交易日，并同时保存三类不可变原始表：

1. 逐笔委托/订单事件：交易日、交易所时间戳、接收时间戳、序号、事件类型、方向、价格、数量、订单号和原订单号；
2. 逐笔成交事件：成交号、价格、数量、金额、买卖订单号，以及供应商是否直接提供主动方方向；
3. 十档盘口快照：买卖一至十档价格和数量、累计成交量、累计成交额、快照类型及交易阶段。

还必须保留交易所、证券代码、数据源、集合竞价/连续竞价/收盘竞价标志。供应商若不提供订单新增、撤单和成交之间的可追溯语义，该数据不能用于LC类研究。

## 数据质量门槛

- 主键不能重复，序号必须可解释地单调；任何缺口必须有供应商重传或缺口标志；
- 连续竞价阶段不能出现未解释的交叉盘口；
- 逐笔汇总的每日成交量和成交额应与独立日线源在0.1%以内一致；
- 必须分别核对集合竞价、上午、下午和收盘竞价，不能跨午间直接连续计算；
- 主动买卖方向若由算法推断，必须另存`INFERRED`标志并保留原始成交，不得覆盖供应商字段；
- 原始层只追加、不修饰；清洗、方向推断、盘口重构和因子聚合分别输出到处理层。

## PV/LC定义冻结门

目前不会猜测PV和LC的全称或公式。进入计算前，两者都必须在因子卡中明确：

- 全称与经济含义；
- 使用哪些订单、成交、撤单或盘口事件；
- 买卖方向判定及无法判定时的处理；
- 聚合窗口、归一化分母、预期方向和目标周期；
- 集合竞价、涨跌停、停牌、序列缺口和异常大单如何处理；
- 同一主假设允许的敏感性参数及总hypothesis count。

只有定义先冻结、数据质量通过，才能开始时间序列检验。没有这些条件时，PV/LC维度属于“重要但阻塞”，不是零价值因子。

## 分阶段获取

第一阶段只购买或导出510300的短期试样，用于验证字段、序列、盘口重构和日线对账，不做参数搜索。试样通过后再决定是否扩展到IF实际合约和沪深300高权重成分。全量五年Level-2成本高，在短样本机制证据和重构质量都未通过前不采购。

机器可读字段与阈值见`config/order_flow_data_contract.yaml`。
