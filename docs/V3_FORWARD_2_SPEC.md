# V3_FORWARD_2零Token前瞻验证规范

## 版本原因

`V3_FORWARD_1`已于2026-08-13产生首条不可变信号。权重与财务数据来源属于冻结规则，因此不能在原版本中删除Tushare依赖。

`V3_FORWARD_2`保持V1的正常化方法、FairPE、`λ=0.3374309932944419`、Edge公式、H1/H2/H3、期限、Gate与Shadow映射不变，只替换前瞻数据供应链。真正OOS起点为2026-08-14。

## 免费数据链

| 数据 | 主来源 | 凭据 |
|---|---|---:|
| 最新成分目录 | 中证指数官网，经AKShare | 无 |
| 最新官方权重 | 中证指数官网，经AKShare | 无 |
| 新增与修订财务 | 东方财富全市场按报告期报表，经AKShare | 无 |
| 指数、ETF与成分收盘 | 新浪、中证指数与现有AKShare接口 | 无 |
| 估值与国债 | 现有AKShare公开接口 | 无 |

中证权重的`trade_date`是官网返回的官方权重日，`observed_date`是本地抓取日，两者永久分开保存。当天抓取到2026-07-31官方权重，不会被标成2026-08-13权重。

## 财务点时语义

- 切换日前只继承V1已经冻结、且当时已可得的历史财务底座；这不是V2未来运行所需的外部依赖；
- 切换日起，新增与修订只来自东方财富；
- 公告日期晚于信号日的数据必须排除；
- 首次看到一个报告期时，`available_at`不早于本地首次发现日；
- 同一报告期内容后来变化时，追加新版本并以首次发现修订之日作为`available_at`，禁止覆盖旧版本；
- 总股本优先由东方财富净利润与每股收益推算；不可得时沿用切换日前最近已知股本，并保留来源字段；
- 每个目标日重新抓取最近5个报告期；断点只允许同一目标日复用。

## 不可变快照与失败规则

每天必须成功抓取中证成分和权重。昨日快照只能用于一致性检查，禁止冒充今日抓取。当天同一快照完全相同才允许幂等重试，实际内容变化会拒绝覆盖。

以下任一条件失败均不生成信号：

- 三条核心收盘序列未共同覆盖信号日；
- 中证成分或权重未成功获取，或证券集合不一致；
- 当前300只财务证券覆盖不足98%；
- 正常化盈利权重覆盖不足98%；
- 当日300只成分收盘不完整；
- 估值或国债超过冻结的新鲜度上限；
- 任一冻结文件指纹变化。

## 日运行

```powershell
& '.\.venv\Scripts\python.exe' '.\scripts\run_v3_forward_2_daily.py'
```

输入刷新状态写入`paper/v3_forward_2_input_refresh_status.json`。市场、估值与国债、中证权重与成分、东方财富财务、成分股收盘五个步骤分别记录开始时间、耗时、成功/失败、最后完成步骤和失败步骤；财务步骤同时记录当日断点目录、前后缓存文件数及是否复用缓存。外层周期状态写入`paper/v3_forward_2_daily_run_status.json`，将输入刷新与Ridge/前向输出分开计时，因此外部超时后仍能定位停留阶段。

信号、Outcome和Shadow日志位于`data/forward/v3_forward_2/`。V1日志永久保留，不与V2拼接后冒充同一OOS序列。
