# 510300 Oracle 信息预算 V1.0.1 保守验收修正规范

## 1. 修正性质

本修正不覆盖 `510300_ORACLE_INFORMATION_BUDGET_V1`。原 V1 的冻结清单、随机种子、误差网格、对抗排序、账户引擎、成本、分红与普通日频夏普结果全部保持不变。

修正启动时，原 V1 结果和四项 Oracle 稳健性审计均已可见。新增结果仅包括此前未计算的逐场景月频、非重叠20日和 Lo/HAC 夏普、遗漏的退出延迟字段、完整可行区域，以及 Atlas 最终治理状态。不得将本修正描述为盲测或严格样本外验证。

## 2. 为什么原 V1 不能直接验收

原 V1 报告普通日频压力净夏普 1.740，但同一完美 Oracle 的月频、20日区间和 Lo/HAC 夏普分别约为 1.278、1.309 和 1.371。序列相关与聚合频率明显压缩了从 1.740 到目标 1.200 的表观空间。原 V1 的误差单元仍只按普通日频夏普判定，且未交付 `MAX_EXIT_DELAY_DAYS` 和 `SHARPE_1_2_FEASIBLE_REGION`，因此其“可推进”只能视为候选裁决。

## 3. 冻结保守夏普

每个误差场景都必须通过原账户执行引擎重放，并同时计算：

- 月度复合账户收益夏普；
- 原 Oracle 完整20日区间的账户复合收益夏普；
- Bartlett 权重、最大滞后20日的 Lo/HAC 日频夏普。

场景保守夏普固定定义为三者最小值：

```text
CONSERVATIVE_SCENARIO_SHARPE
= min(MONTHLY_SHARPE, TWENTY_DAY_INTERVAL_SHARPE, LO_HAC_SHARPE_Q20)
```

普通日频夏普继续报告并用于复刻原 V1，但不再决定保守验收。

## 4. 冻结误差与通过规则

随机种子、每单元500次、逐轴整数网格、6×6×6联合网格、对抗排序、0—10日进入/提前退出/延后退出，均与 V1 完全相同。

随机单元必须同时满足：保守夏普5%分位数不低于1.2、保守夏普达到1.2的概率不低于95%、总收益5%分位数为正、最大回撤落在原全仓回撤80%以内的概率不低于95%。对抗与时序单元必须同时满足保守夏普不低于1.2、总收益为正和相同回撤门。

## 5. 边界和删失

所有边界使用连续前缀或后缀规则，禁止跳过失败点挑选后来偶然通过点。若延后退出在冻结0—10日网格内全部通过，`MAX_EXIT_DELAY_DAYS`必须报告为“至少10日、右删失、真实上限未识别”，不得伪写成精确最大值10。

`SHARPE_1_2_FEASIBLE_REGION`必须覆盖联合网格全部216个单元，同时给出随机95%稳健门、对抗门及二者交集，不能只报告最低精确率单点。

## 6. 晋级与停止门

只有保守口径同时允许：对抗性上涨召回要求不高于80%、至少误入1个大跌区间、至少误入10个震荡区间、至少延迟入场3日，并且随机与对抗联合可行区域交集非空，才可将 UP20 分支写成“仅有资格冻结研究协议、尚未创建”。

任一门失败时，正式状态为：

```text
ORACLE_VALUE_NOT_REALISTICALLY_ACCESSIBLE
```

这不是否定完美信息的经济价值，而是停止把该价值自动转译为现实预测器目标。

## 7. 永久治理边界

Atlas 固定为 `REJECTED_FROZEN`，Factor Router 固定为 `SKIPPED_NOT_CREATED`。`contribution_hhi20` 与 `price_trend_z120` 只进入零仓位观察账本，保持原方向、原窗口、原阈值，不组合、不降门、不自动晋级。无论本修正结果如何，都不创建现实模型、不读取现实策略回报、不输出仓位、不生成订单、不连接券商、不授权实盘。
